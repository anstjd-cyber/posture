# 거북목 측정 부스 — 운영 가이드

웹캠으로 목 각도를 재서 거북목 점수를 보여주는 부스 체험 앱입니다.
모든 처리는 브라우저 안에서 일어나고 **영상은 저장도 전송도 하지 않습니다.**

## 공개 주소

| | 주소 |
|---|---|
| 시작 페이지 | https://anstjd-cyber.github.io/posture/ |
| 측정 앱 | https://anstjd-cyber.github.io/posture/booth/ |
| 결과·스트레칭 | https://anstjd-cyber.github.io/posture/result/ |

저장소: https://github.com/anstjd-cyber/posture

> **부스에서는 공개 주소가 아니라 이 폴더의 `start.bat` 으로 실행하세요.**
> 행사장 와이파이가 끊겨도 돌아가야 하기 때문입니다.
> 공개 주소는 홍보·사전 체험·노트북 고장 시 백업용입니다.
>
> 이 폴더의 `index.html` 을 고쳤다면 공개본에도 반영해야 합니다
> (아래 "파일 구성 → 공개본과 어디가 짝인지" 참고 — `booth/index.html` 로 덮어쓰면 됩니다).

## 1. 처음 한 번만 — 오프라인 준비

**행사장에 나가기 전, 인터넷이 되는 곳에서** `download-offline.bat` 을 더블클릭하세요.
AI 모델과 실행 런타임(약 24MB)을 프로젝트 안에 내려받습니다.

이걸 안 하면 앱이 인터넷에서 모델을 받아오려고 합니다. 행사장 와이파이는 거의 항상
불안정하니 **반드시 미리 받아두세요.**

> 확인 방법: 앱을 띄우고 `C` 키 → 맨 아래 `모델 자산`이 **로컬 (오프라인 OK)** 로 보이면 완료.

---

## 2. 실행

`start.bat` 더블클릭 → 크롬이 열립니다. `F11` 로 전체화면.

- 측정 화면: `http://localhost:8000/index.html`
- 집계 화면: `http://localhost:8000/index.html#dashboard` ← 보조 모니터용, 별도 창으로

> `index.html` 을 그냥 더블클릭하면 **카메라가 동작하지 않습니다.**
> 브라우저가 `file://` 페이지에 카메라를 허용하지 않기 때문입니다. 반드시 `start.bat` 으로 실행하세요.

### 단축키

| 키 | 기능 |
|---|---|
| `O` | 운영자 패널 (임계값·QR 주소·카메라·CSV) |
| `C` | 캘리브레이션 오버레이 (실시간 원시 수치) |
| `D` | 집계 화면 전환 |
| `Esc` | 대기화면으로 즉시 복귀 |
| `F11` | 전체화면 |

> **부스에서는 `← 시작 페이지` 링크가 나타나지 않습니다.** 공개 주소(`/posture/booth/`)로
> 접속했을 때만 화면 우상단에 뜹니다(집계화면 제외. 측정 중에는 품질 칩과 겹치지 않게
> 한 칸 아래에 표시). 부스에서는 앱이 서버 루트에 있어
> 돌아갈 상위 페이지가 없고, 체험자가 실수로 앱을 벗어나면 안 되기 때문입니다.

## 3. ⚠ 오픈 전에 반드시 — 캘리브레이션

**이 단계를 건너뛰면 부스가 망합니다.**

거북목의 임상 지표인 **CVA(두개척추각)** 는 **C7 극돌기와 귀 이주를 잇는 선이 수평선과
이루는 각도**입니다. 정상 53~55° 이상, 거북목 44~54° 미만으로 **연구마다 다릅니다.**

**이 앱의 각도는 CVA 가 아닙니다.** 웹캠은 C7 을 볼 수 없어 **어깨 관절점**을 기준으로 쓰고,
수평선이 아니라 **수직(90°)** 을 기준으로 잽니다. 기준점도 기준선도 달라서
**CVA 기준값을 그대로 넣으면 안 됩니다.** 숫자 범위가 우연히 겹쳐 보여 더 위험합니다.

마커 없이 웹캠으로 잰 귀-어깨 각도에 대한 공개 기준값은 찾지 못했습니다(스마트폰 CVA
연구들은 전부 C7 에 마커를 붙입니다). 그래서 **기준값은 우리 장비에서 직접 재는 수밖에
없습니다.** 상대 비교는 잘 맞으니, 양끝만 맞추면 됩니다.

### 사람이 아니라 자세를 기준으로 삼는다

직원들이 모두 거북목이면 표본이 치우치지 않을까 걱정될 수 있습니다. 다행히
**사람과 무관한 고정 기준점이 있습니다.**

이 앱은 `atan2(귀가 어깨보다 위인 정도, 귀가 어깨보다 앞인 정도)` 로 각도를 구합니다.
**귀가 어깨 바로 위에 오면 앞뒤 차이가 0 이 되어 각도는 수학적으로 정확히 90°** 입니다.
키·체형·거리와 무관합니다. 게다가 귀-어깨 정렬은 자세 평가의 고전적 기준선
(귀 → 어깨 → 고관절 → 무릎 → 복사뼈)이라 **90° 가 곧 교과서적 중립**입니다.

그래서 아래 절차는 **평균이 아니라 최댓값**을 쓰고, **90° 와 비교해 검산**합니다.

### 절차 (10분)

1. 카메라를 삼각대에 올리고 **가슴 높이**로 맞춘 뒤 **움직이지 않게 고정**합니다.
   (이후 카메라 높이나 거리를 바꾸면 캘리브레이션을 다시 해야 합니다.)
2. 바닥에 발자국 테이프를 붙입니다 — **측면용 1세트, 정면용 1세트.**
   카메라에서 1.5~2m, 측면 세트는 카메라를 향해 90° 돌아선 방향으로.
3. `start.bat` 실행 → `C` 키로 캘리브레이션 창을 엽니다.
4. 직원 5~6명이 번갈아 측면 발자국에 서서 **`목 각도 (raw)`** 값을 적습니다.
   - 바른 자세(턱 당기고 귀가 어깨 위)로 한 번
   - 일부러 거북목 자세(머리를 앞으로)로 한 번

   > **한 명은 '검증된 중립'으로 따로 재두면 가장 확실합니다.** `C` 키 화면에 찍히는
   > 랜드마크 점을 보면서, 옆에서 **귀 점이 어깨 점 바로 위에 오도록** 맞춰준 뒤 값을
   > 읽습니다. 그 사람이 평소 거북목이든 아니든 상관없습니다 — 자세를 본 것이기 때문입니다.

5. **검산부터 합니다.** 바른 자세 값 중 **가장 높은 값**을 90° 와 비교하세요.
   - **85~95° 근처** → 정상입니다. 다음으로 넘어갑니다
   - **70° 처럼 한참 낮다** → 표본 문제가 아니라 **장비 문제**일 가능성이 큽니다.
     카메라 높이가 안 맞거나, 발자국보다 비스듬히 섰거나, 랜드마크가 어깨를 잘못 잡은 것.
     **그대로 넣지 말고 원인부터 확인하세요.**

6. `O` 키로 운영자 패널을 열고 **두 값만** 넣습니다.
   - **100점 각도** : 바른 자세들의 **최댓값**보다 **3° 높게**
   - **0점 각도** : 거북목 자세들의 **평균**보다 **3° 낮게**

   > **왜 한쪽은 최댓값인가** — 구조적으로 목을 못 펴는 사람이 섞이면 평균이 끌려
   > 내려갑니다. 최댓값이 '이 장비에서 도달 가능한 중립'에 가장 가깝습니다.
   > 거북목 쪽은 누구나 머리를 앞으로 뺄 수 있어 평소 자세와 무관하므로 평균으로 충분합니다.

   > 등급은 점수를 20점씩 자른 구간이라, 이 두 값만 맞추면 등급 경계는 자동으로 따라옵니다.
   > 이렇게 넣으면 바른 자세가 A, 일부러 만든 거북목 자세가 E 근처에 떨어지고
   > 그 사이 사람들이 B~D 에 퍼집니다.
7. `결과화면 미리보기` 버튼으로 점수와 등급이 납득 가능한지 확인합니다.
8. **마지막에 `기록 전체 삭제`** — 리허설 데이터가 집계 평균에 섞이면 안 됩니다.

### 참고 — 기본값과 그 뜻

운영자가 맞추는 값은 둘뿐입니다.

| 값 | 기본 | 의미 |
|---|---|---|
| 낮은 쪽 각도 | 70° | 이 각도면 약 5점 |
| 높은 쪽 각도 | 88° | 이 각도면 약 95점 (90° = 귀가 어깨 바로 위) |

등급은 점수에서 자동으로 나옵니다. **각도로 등급 경계를 따로 지정하지 않습니다.**

| 등급 | 점수 | 이름 | 기본값에서의 각도 |
|---|---|---|---|
| A | 81~100 | 아주 좋아요 | 83.4° 이상 |
| B | 61~80 | 양호 | 80.4°~83.3° |
| C | 41~60 | 주의 | 77.9°~80.3° |
| D | 21~40 | 거북목 의심 | 75.0°~77.8° |
| E | 0~20 | 거북목 심함 | 75.0° 미만 |

점수는 직선이 아니라 S자 곡선으로 환산한다 — 사람이 몰리는 가운데에서 더 촘촘하고
양 끝은 완만해 0·100 에 잘 붙지 않는다. 각도 칸은 기본값(70°·88°)에서 계산한 값이라, 캘리브레이션하면 따라 움직입니다.
**점수 구간은 언제나 20점씩 고정입니다.**

각도가 **클수록 좋습니다** (머리가 어깨 위에 있다는 뜻).

## 4. 결과 QR 설정

**이미 설정돼 있습니다. 그대로 쓰시면 됩니다.**

결과 페이지는 아래 주소로 배포돼 있고, 앱의 기본값으로 들어가 있습니다.

> **https://anstjd-cyber.github.io/posture/result/**

결과 QR은 체험자 **휴대폰**으로 열립니다. 그래서 결과 페이지는 부스 노트북이 아니라
외부(GitHub Pages)에 올라가 있어야 합니다. 체험자는 자기 폰 데이터로 열기 때문에
**행사장 와이파이가 죽어도 QR은 정상 동작합니다.**

QR은 이렇게 만들어집니다.

```
https://anstjd-cyber.github.io/posture/result/#s=72&g=B&a=74.3&b=96
                                                 점수 등급  각도   어깨균형
```

점수를 URL에 직접 담으므로 **서버도 DB도 필요 없고, 개인정보는 아무것도 수집하지 않습니다.**

### 확인해 두면 좋은 것

- 오픈 전에 위 주소를 **휴대폰으로 한 번 열어보세요.**
- `O` → `결과화면 미리보기` 로 결과 카드를 띄운 뒤, 실제로 **QR을 폰으로 스캔**해 보세요.
- QR이 어디를 가리키는지는 QR 위에 마우스를 올리면 뜹니다.
- 주소를 바꾸고 싶으면 `O` → `결과 페이지 주소` 에서 수정하면 즉시 반영됩니다.
  (비워두면 QR 자리에 안내 문구가 나오고, 앱은 그대로 동작합니다.)

> 전에 이 앱을 띄운 적이 있는 PC라면 예전 주소가 브라우저에 저장돼 있을 수 있습니다.
> `O` → `설정 초기화` 를 누르면 위 주소로 돌아옵니다.

## 5. 체험 흐름 (약 70초)

```
대기화면
 → 사람이 감지되면 자동 시작 (또는 화면 터치)

> **자동 시작은 부스에서만 동작합니다.** 공개 주소(`/posture/booth/`)에서는 책상에 앉은
> 사람이 이미 카메라에 잡혀 있어 누르지도 않았는데 시작돼 버리므로, 화면을 눌러야 시작합니다.

 → [1단계] 측면 발자국에 옆으로 서기 → 자세 확인 → 3·2·1 → 2초 측정
 → "정면으로 돌아주세요" (자동 전환)
 → [2단계] 정면 발자국 → 3·2·1 → 2초 측정
 → 결과 + QR (30초)
 → 대기화면 복귀
```

- 자세가 흔들려 유효 프레임이 부족하면 자동으로 다시 측정합니다.
- 측정 도중 사람이 사라지면 18초 후 대기화면으로 돌아갑니다.
- 한 프레임으로 판정하지 않고 2초간 수집한 값들의 **중위값**을 씁니다.

### 처리량

체험 1회가 70~90초이므로 **시간당 30~35명**이 한계입니다. 피크에 줄이 길어질 것 같으면:

- 노트북을 2대로 늘려 2레인 운영 (이 폴더를 그대로 복사하면 됩니다)
- 대기줄에서 미리 설명해주는 인력 1명 배치

### 자세 전환이 가장 큰 병목입니다

"측면 → 정면" 전환에서 사람들이 제일 많이 헤맵니다.
**바닥 발자국 테이프 2세트가 화면 안내 문구보다 훨씬 효과적입니다.**

## 6. 집계 화면

`D` 키 또는 `#dashboard` 주소로 엽니다. 오늘 측정 인원, 평균 점수, 평균 목 각도,
거북목 의심 비율, 등급 분포, 최근 10건을 보여줍니다.

- 보조 모니터에 띄워두면 사람을 끌어모으는 효과가 큽니다.
- 같은 브라우저의 별도 창으로 열면 측정될 때마다 자동 갱신됩니다.
- 저장되는 것은 **점수·각도·등급·시각**뿐입니다. 영상·사진·식별정보는 없습니다.
- 데이터는 그 브라우저에만 남으므로 **행사 종료 시 `O` → `CSV 내보내기`** 를 꼭 하세요.
  (브라우저 캐시를 지우면 사라집니다.)

## 7. 현장 준비물

- 노트북 (크롬) + 전원 + 멀티탭
- 웹캠 + **삼각대** (가슴 높이)
- 바닥 발자국 테이프 **2세트** (측면용 / 정면용) + 측면 방향 화살표
- 단색 배경천 (인식률이 올라갑니다)
- 조명 1개 — **카메라를 향한 역광은 피하세요**
- 보조 모니터 (집계 화면용, 선택)

## 8. 문제가 생기면

| 증상 | 원인과 조치 |
|---|---|
| "카메라를 열 수 없습니다" | 주소창 왼쪽 자물쇠 → 카메라 **허용**. 줌·팀즈가 카메라를 잡고 있으면 종료. USB 웹캠은 다시 꽂고 `F5`. |
| "자세 인식 모델을 불러오지 못했습니다" | `download-offline.bat` 을 실행하지 않았고 인터넷도 없는 상태입니다. |
| 카메라가 동작하지 않음 | `index.html` 을 직접 더블클릭했을 가능성. `start.bat` 으로 실행하세요. |
| "측면 아님" 이 계속 뜸 | 몸을 덜 돌린 상태입니다. 발자국 방향을 확인하세요. 그래도 안 되면 `O` → `측면 비율 ≤` 를 0.6 정도로 올립니다. |
| "정면 아님" 이 계속 뜸 | `O` → `정면 비율 ≥` 를 0.8 정도로 낮춥니다. |
| 전원이 C~D 등급 | **캘리브레이션을 안 했습니다.** 위 3번을 하세요. |
| 전원이 A 등급 | 같은 원인. 경계값을 올리세요. |
| 측정이 자꾸 다시 시작됨 | 자세 유지가 안 되는 것입니다. `O` → `최소 유효 프레임` 을 15 정도로 낮춥니다. |
| 너무 빨리/느리게 넘어감 | `O` → 타이밍 항목(`자세 유지`, `카운트다운`, `측정 시간`, `결과 유지`)을 ms 단위로 조절. |

## 9. 이 측정의 한계 (체험자가 물어보면)

- **의료기기가 아닙니다.** 진단에 쓸 수 없고, 화면에도 그렇게 표시됩니다.
- 웹캠은 기준점이 되는 목뼈(C7)를 볼 수 없어 **어깨 관절점으로 근사**합니다.
  그래서 각도 절대값보다 **상대 비교와 경향**에 의미가 있습니다.
- 자세는 순간순간 달라집니다. 2초 측정 한 번은 그 순간의 스냅샷입니다.
- 어깨 균형은 참고용 보조 지표이며, 거북목 점수와는 **별개로** 계산됩니다.
  (두 지표를 섞으면 숫자가 무슨 뜻인지 아무도 설명할 수 없게 됩니다.)

## 파일 구성

```
index.html                 측정 앱 전체 (단일 파일 — 수정/복사가 쉽도록)
start.bat / start.ps1      로컬 서버 실행 + 브라우저 열기
download-offline.bat/.ps1  모델·런타임 내려받기 (사전 1회)
models/                    자세 인식 모델 (약 5.6MB)
vendor/                    MediaPipe 런타임, QR 생성 라이브러리
result-page/               QR이 열어줄 결과·스트레칭 페이지 (외부에 따로 호스팅)
start-page/                공개 주소의 첫 화면 (외부에 따로 호스팅)
```

`result-page/` 와 `start-page/` 는 부스 노트북이 아니라 **인터넷에 올라가야** 하는
파일입니다. 부스 노트북에 복사해둬도 해롭진 않지만, 거기서는 쓰이지 않습니다.
